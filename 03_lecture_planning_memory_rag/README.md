# Демо к Лекции 3 — практика «у відкриту»

Минималистичные, максимально прозрачные демо: **чистый Python + `requests`**, без
LangChain/LangGraph. Каждый шаг печатается на экран, чтобы студенты видели механику
изнутри. Фреймворковые версии тех же идей — в `../lecture_examples/`.

Исключение одно и намеренное: `03_langgraph/` — та же память и тот же RAG, но
собранные на фреймворке. Он показывается последним, чтобы было с чем сравнивать.

Тайминг: вся лекция — 2 часа, теория ~90 мин → на живую практику **~30 мин**.

## Состав

| Что | Где | Мин |
| --- | --- | --- |
| Планирование | `001_plan_and_execute.py` | 6 |
| Память | `01_memory/` — агент DevMate, отдельный репозиторий по шагам | ~ |
| RAG | `02_rag/` — пять скриптов, см. `02_rag/README.md` | 22 |
| Фреймворк | `03_langgraph/` — те же память и RAG на LangGraph | 5 |

### `001_plan_and_execute.py` — планирование

План как **данные**: LLM выдаёт машиночитаемый JSON-план, наш executor выполняет
шаги с бюджетом и `stop_reason`.
На экране: `[GOAL] [PLAN] [STEP] [OBSERVE] [RESULT]`.

Показывать так: сначала `[PLAN]` (план — это данные, их можно проверить до
выполнения), затем бюджет (`MAX_STEPS=1`) — почему у агента должен быть предел.

### `01_memory/` — память

Агент DevMate с тремя хранилищами: история сессии, `memories/*.md` и архив
`state.db`. Разложен по шагам (`docs/steps/`), каждый шаг — рабочее состояние.
Своя документация внутри.

### `02_rag/` — поиск и RAG

Продолжение блока памяти на том же материале: полнотекстовый поиск по архиву
промахнулся на словоформе → нужен поиск по смыслу. Четыре скрипта +
домашнее задание. Всё описано в `02_rag/README.md`.

### `03_langgraph/` — то же самое, но на фреймворке

Один агент: DevMate из `01_memory/` + RAG из `02_rag/`, собранные на LangGraph.
Ценность не в функциональности, а в **диффе**: 1573 строки ручной механики
превращаются в 338 строк кода, и `safety.py` переезжает файл-в-файл, без единой
правки — фреймворк съел механику и не съел ни строки политики.

На лекции — 5 минут и одна таблица; это референс-репозиторий, который читают
дома. `03_langgraph/README.md` написан так, чтобы читаться без преподавателя.
Свои зависимости, свой `requirements.txt`; `.env` общий.

## Запуск

```bash
cp .env.example .env      # вписать OPENAI_API_KEY
pip install requests python-dotenv
python 001_plan_and_execute.py
cd rag && python r1_keyword_vs_embeddings.py    # дальше по rag/README.md
cd ../langgraph && python3 -m venv .venv        # блок на фреймворке — свои зависимости
.venv/bin/pip install -r requirements.txt && .venv/bin/python -m devmate_lg.cli
```

Эмбеддинги на лекции не считаются: векторы лежат в `02_rag/vectors.json`.
Переменные `EMBED_*` нужны, только чтобы пересчитать этот кеш.

Каждый файл заканчивается блоком **«Твоя черга»** — микро-упражнение для студентов.

## Чего здесь больше нет

`002_memory.py` и `003_agentic_rag.py` удалены осознанно:

- **`002_memory.py`** — его сцены A и C перекрыты демо `01_memory/` на настоящем
  механизме вместо постановки на `json.dump`.
- **`003_agentic_rag.py`** — заменён на `02_rag/r3_agentic_rag.py` один в один:
  та же логика `route → retrieve → grade → rewrite → generate`, но ретривер
  общий с `02_rag/r2_traditional_rag.py` (иначе сравнение стоимости нечестное) и
  добавлен счётчик вызовов LLM.

**Дырка, которую закрыли сознательно.** У `002` была сцена B — windowing:
обрезали окно, агент забыл имя. Демо `01_memory/` её не покрывает: DevMate историю
**сжимает** (`compress.py`), а не обрезает. Windowing как тип памяти
(`trim_messages`) остаётся в теории — проговаривается на слайде со ссылкой на
`../lecture_examples/02_context_window_trim_by_messages.py`. Размен осознанный:
сжатие показывает ту же проблему «контекст не резиновый» на более честном
механизме.
