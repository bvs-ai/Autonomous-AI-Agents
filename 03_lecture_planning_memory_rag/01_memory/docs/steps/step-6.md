# Крок 6 — агент вчиться сам, людина лишає за собою право вето

Два механізми, які мають сенс лише разом. Перший робить запис у пам'ять
автоматичним. Другий — оборотним.

## Чому навчання не може жити всередині ходу

На кроках 2–3 агент зберігав факти інструментом `memory` посеред роботи.
Механізм працює, але спрацьовує нерівномірно: у розпал задачі модель зайнята
задачею. Пам'ять програє конкуренцію за увагу рівно тоді, коли розмова
найзмістовніша.

Hermes виносить навчання в окремий прохід **після** відповіді користувачу.
У цьому виклику задачі, з якою пам'ять конкурувала б, просто немає:

```python
PROMPT = """\
Ти — фоновий процес самонавчання агента DevMate. Користувач тебе не бачить \
і відповіді від тебе не чекає.
...
Нічого вартого немає — так і скажи одним рядком, не викликаючи інструментів. \
Порожня пам'ять краща за засмічену.
"""
```

Останній рядок важливіший, ніж здається. Модель, яку попросили щось зробити,
схильна це зробити — і без явного дозволу нічого не робити ревʼю почне
записувати дрібниці, аби виправдати свій виклик.

## Порядок: спершу відповідь, потім навчання

Ревʼю коштує зайвий виклик моделі й пару секунд. Платити ними до відповіді
не можна, тому воно винесене з `run_turn` в окремий метод:

```python
def after_turn(self) -> None:
    if self.turns_since_review < review.TURNS_BETWEEN_REVIEWS:
        return
    self.turns_since_review = 0      # скидаємо ДО виклику
    verdict = review.review(self.history, self.on_tool)
```

А CLI викликає його після того, як панель з відповіддю вже надрукована:

```python
try:
    console.print(Panel(agent.run_turn(text), ...))
except Exception as exc:
    console.print(f"[red]помилка:[/] {exc}")
    continue                          # перерваний хід ревʼю не заслуговує

agent.after_turn()
```

Три деталі, кожна з яких — наслідок конкретної помилки:

**Лічильник росте лише на успішній відповіді.** Хід, що впав у ліміт
ітерацій, у транскрипті лишає купу викликів інструментів без висновку —
вчитися там нема на чому.

**Скидання до виклику, а не після.** Інакше ревʼю, яке впало з помилкою
мережі, повторюватиметься кожного наступного ходу.

**Перерваний хід не ревʼюється** — `continue` в гілці помилки.

У Hermes цей самий порядок досягається фоновим однопотоковим executor'ом. У
нас синхронно: механізм видно краще, а для одного користувача в терміналі
результат той самий. Різницю чесно зафіксовано в `hermes-mapping.md`.

## Дайджест замість транскрипту

Ревʼю отримує не історію повідомлень, а плаский текст:

```python
def _digest(history: list[dict]) -> str:
    lines = []
    for m in history[-DIGEST_MESSAGES:]:
        content = (m.get("content") or "").strip()
        if not content:
            continue
        role = {"user": "Користувач", "assistant": "DevMate", "tool": "Інструмент"}
        lines.append(f"{role.get(m['role'], m['role'])}: {content[:600]}")
    return "\n".join(lines)
```

Чому не передати історію як є? Тому що ревʼю може ходити в **іншу** модель
(`REVIEW_MODEL` у `.env`) — а чужий prefix cache усе одно не перевикористати.
Щойно економія на формі повідомлень зникає, вигідніше віддати компактний
текст: `tool_calls` ревʼю не цікавлять, йому потрібен зміст розмови.

Схема інструмента передається одна:

```python
[s for s in tools.SCHEMAS if s["function"]["name"] == "memory"]
```

Ревʼю не має читати файли й запускати команди. Звузити набір інструментів
дешевше й надійніше, ніж просити в промпті ними не користуватися.

Другого виклику моделі після інструмента немає навмисно: результат нікому
читати, ревʼю на цьому закінчується.

## Гейт: єдина точка входу

Агент, що пише в пам'ять сам — а тепер ще й фоново, без відома користувача, —
рано чи пізно запише хибне припущення. Записи їдуть у системний промпт
кожної наступної сесії, тож одна помилка живе роками.

`memory.apply()` став точкою розгалуження, а колишня логіка запису переїхала
в `_commit()`:

```python
def apply(target: str, operations: list[dict], source: str = "agent") -> str:
    if WRITE_APPROVAL:
        return _enqueue(target, operations, source)
    return _commit(target, operations)
```

Ключове тут — що така точка одна. Інструмент `memory`, фонове ревʼю, а з
кроку 8 і провайдери — усі пишуть через `apply()`. Нового способу писати
повз гейт не існує, тому й перевірка потрібна в одному місці.

## Черга бреше моделі, і це навмисно

```python
return (
    f"Зміну поставлено в чергу на підтвердження (#{_next_id - 1}). "
    "Продовжуйте — повторювати запис не потрібно."
)
```

Відповідь виглядає як успіх. Скажи ми «запис заблоковано» — модель почне
його повторювати іншими словами, шукати обхід або виправдовуватись перед
користувачем. Ні те, ні інше не корисне: рішення все одно за людиною.

Черга живе в пам'яті процесу. На диску вона вимагала б власного формату й
міграцій, а механізм від цього не змінюється.

## Що видно наживо

**Модель вважає, що запам'ятала.** З увімкненим гейтом на «запам'ятай: тести
запускаються командою pytest -q» агент відповідає «Запам'ятав.» — хоча на
диску нічого немає, запис стоїть у черзі. Наочна ілюстрація того, що
відповідь агента про власний стан — не доказ.

**Ревʼю вміє відмовлятися.** Реальний вердикт після трьох ходів:

> Нічого вартого немає — уподобання про стислі відповіді вже збережено, а
> згадка про лекцію в четвер — тимчасовий стан задачі.

Обидві частини правильні, і обидві неочевидні. Перша — тому що ревʼю бачить
**живу** пам'ять (`memory.render_all()`), а не заморожений знімок агента з
кроку 2; інакше воно продублювало б запис, зроблений хвилину тому. Друга —
розрізнення стійкого факту й тимчасового стану, найважче місце всієї теми.

## Перевірити

Три буденні ходи, не просячи нічого запам'ятати:

```bash
.venv/bin/python -c "
from devmate.agent import Agent
a = Agent(on_tool=lambda n,ar,r: print(f'[{n}] {ar}'),
          on_review=lambda v: print(f'>>> REVIEW: {v}'))
for t in ['я Борис, викладаю агентні системи. Які файли в devmate?',
          'подобаються стислі відповіді без води. Скільки рядків у agent.py?',
          'дякую, це для лекції в четвер']:
    print(a.run_turn(t)); a.after_turn()"
```

Потім гейт — у REPL:

```
/approval on
запам'ятай: тести запускаються командою pytest -q
/memory       # на диску порожньо
/pending      # #1 → memory (agent) add: Тести запускаються...
/approve 1
/memory       # тепер записано
```
