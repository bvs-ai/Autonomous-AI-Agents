усе подальше або використовує його напряму, або копіює його топологію.

## Прив'язка інструментів

```python
llm_with_tools = llm.bind_tools(safe_tools)
```

Що відбувається фізично: з кожної `@tool`-функції витягується ім'я, docstring
і JSON-схема аргументів; усе це додається в тіло HTTP-запиту. Модель отримує
перелік доступних функцій і може повернути `tool_calls` замість тексту.

`llm` при цьому **не змінюється** — `bind_tools` повертає новий об'єкт. Тому
в кроці 8 спокійно живе другий варіант з іншим набором інструментів.

Головне: інструменти — це **параметр запиту**, а не властивість моделі. Один
і той самий `llm` у різних вузлах може мати різні набори.

## Системний промпт

```python
SYSTEM_PROMPT = """Ти — інтелектуальний асистент-агент. Відповідай українською мовою.
Ти маєш доступ до інструментів: calculator, current_datetime, wikipedia_search, http_get.
Перед відповіддю на фактологічне питання ЗАВЖДИ використовуй відповідний інструмент.
Для обчислень ЗАВЖДИ використовуй calculator, не рахуй самостійно.
Відповідай стисло та по суті. Якщо інструмент повернув помилку, повідом користувача."""
```

Кожен рядок вирішує конкретну проблему:

| Рядок | Що станеться без нього |
|---|---|
| «Відповідай українською» | модель дрейфує на англійську |
| перелік інструментів | дублює схему словами — на практиці підвищує влучність |
| «ЗАВЖДИ використовуй calculator» | модель рахує в умі й помиляється на великих числах |
| «Відповідай стисло» | довгі відповіді, більше токенів |
| «Якщо інструмент повернув помилку, повідом» | замикає контракт `{"status": "error"}` з кроку 2 |

Капслок у «ЗАВЖДИ» — не емоція, а робочий прийом. Промпт — це конфігурація
поведінки, і зберігається він у коді, поруч із рештою.

## Вузол агента

```python
def agent_node(state: MessagesState) -> dict:
    messages = state["messages"]
    if not messages or not isinstance(messages[0], SystemMessage):
        messages = [SystemMessage(content=SYSTEM_PROMPT)] + messages
    response = llm_with_tools.invoke(messages)
    return {"messages": [response]}
```

Чотири рядки, три ідеї:

1. **Перевірка `isinstance(messages[0], SystemMessage)` обов'язкова**, бо
   вузол викликається в циклі багато разів. Без неї кожен прохід додавав би
   ще один системний промпт.
2. **Локальна змінна `messages` у стан не пишеться.** Промпт живе тільки
   всередині виклику — у стрічці повідомлень його немає.
3. **Повертається зміна, а не стан.** `{"messages": [response]}` — один новий
   елемент, редьюсер `add_messages` допише його в кінець.

Зверніть увагу: вузол **не вирішує**, чи йти в інструменти. Рішення — на
ребрі.

## Вузол інструментів

```python
tool_node = ToolNode(safe_tools)
```

Готовий компонент. Його логіка: взяти останній `AIMessage`, пройти по
`tool_calls`, для кожного знайти функцію за іменем, перевірити аргументи
схемою, викликати, загорнути результат у `ToolMessage` з тим самим
`tool_call_id`. Якщо викликів кілька — виконає всі.

## Граф

```python
react_graph = StateGraph(MessagesState)
react_graph.add_node("agent", agent_node)
react_graph.add_node("tools", tool_node)
react_graph.add_edge(START, "agent")
react_graph.add_conditional_edges(
    "agent",
    tools_condition,
    {"tools": "tools", END: END}
)
react_graph.add_edge("tools", "agent")     # ← цикл
react_agent = react_graph.compile()
```

```
START ──> agent ──(є tool_calls?)──> tools ──┐
             │ ні                            │
             └──> END                        │
             ^─────────────────────────────── ┘
```

**`tools_condition`** — готова функція: дивиться на останнє повідомлення,
є `tool_calls` — повертає `"tools"`, немає — `END`. Третій аргумент —
таблиця «мітка → вузол».

**Рядок `add_edge("tools", "agent")` — найважливіший у файлі.** Він замикає
цикл. Без нього це був би лінійний конвеєр: один виклик інструмента і кінець.
З ним агент може ітеративно: порахувати → подивитись дату → знайти факт →
відповісти.

Скільки буде ітерацій — **не знає ніхто, включно з автором коду**. Цикл
закінчиться, коли модель поверне повідомлення без `tool_calls`. Тобто умову
виходу контролює модель. Саме тому потрібен крок 5.

**`compile()`** перетворює опис на об'єкт, який можна запускати, і перевіряє
граф на помилки (недосяжні вузли тощо). Тут — без checkpointer, тому стан
живе лише всередині одного `invoke`.

Зверніть увагу, що з файлу експортуються **два** імені: `react_graph` (опис) і
`react_agent` (скомпільований об'єкт). У кроці 7 той самий `react_graph` буде
скомпільовано вдруге — вже зі збереженням стану.

## Демо: три запити на три інструменти

```python
test_queries = [
    "Скільки буде 1234 * 5678 + 99?",   # → calculator
    "Яка сьогодні дата?",                # → current_datetime
    "Хто такий Тарас Шевченко?",         # → wikipedia_search
]
```

Ніякої маршрутизації в коді немає — інструмент обирає модель за описами.

```python
result = react_agent.invoke({"messages": [HumanMessage(content=q)]})
final = result["messages"][-1]
print(f"🤖 Відповідь: {get_text(final.content)}")

tool_calls = [m for m in result["messages"] if isinstance(m, ToolMessage)]
if tool_calls:
    print(f"🔧 Інструменти: {[m.name for m in tool_calls]}")
```

Два спостереження:

- **`invoke` повертає весь фінальний стан**, а не тільки відповідь. Відповідь —
  останній елемент `messages`, вся історія доступна.
- **Трасування безкоштовне**: відфільтрували `ToolMessage` — і видно, які
  інструменти реально викликались. З цієї ідеї в кроці 4 виросте
  `TrajectoryLogger`.

## Перевірити

```bash
.venv/bin/python step3_react.py
```

Найкорисніше — подивитись на стрічку повідомлень цілком:

```bash
.venv/bin/python -c "
from step3_react import react_agent
r = react_agent.invoke({'messages': [{'role': 'user', 'content': 'Порахуй 17*23 і скажи, який сьогодні день'}]})
for m in r['messages']:
    print(type(m).__name__, '|', (m.content or '')[:70], '|', getattr(m, 'tool_calls', None))
"
```

Видно чергування: Human → AI(tool_calls) → Tool → AI(tool_calls) → Tool →
AI(текст). Це і є цикл ReAct.

Спробуйте запит, який не потребує інструментів («Привіт, як справи?») — у
стрічці буде лише два повідомлення, бо `tools_condition` одразу поверне `END`.
