# DevMate LG — те саме застосування, але на LangGraph

Четвертий блок демо до Лекції 3. Це **не набір прикладів**, а один агент: той
самий DevMate із `../01_memory/`, зібраний на фреймворку, з RAG із `../02_rag/`
всередині.

Цінність тут не у функціональності, а в **дифі**: що з ручної механіки забирає
собі фреймворк — і що лишається вашим кодом при будь-якому фреймворку.

Без попередніх блоків цей не має сенсу: механіка памʼяті розібрана на восьми
кроках `../01_memory/docs/steps/`, механіка RAG — на пʼяти скриптах `../02_rag/`.
Тут вона не пояснюється заново, тут видно, куди вона поділась.

## Запуск

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m devmate_lg.cli
```

`.env` спільний з рештою демо — той самий, що для `../02_rag/` (`OPENAI_BASE_URL`,

Ембединги на лекції не рахуються: вектори лежать у `../02_rag/vectors.json`, і
памʼять індексується з того самого кеша. **Пошук не робить жодного мережевого
виклику** — ані по корпусу, ані по памʼяті. Мережа потрібна тільки моделі.

## Три цикли, і вони різні

Головне, що варто винести: «агент думає» — це не один цикл, а три, з різними
станами й різними бюджетами.

```
┌─ Цикл 1: розмова ─ create_react_agent ─────────────────────┐
│  model ↔ tools, поки модель не відповість текстом          │
│  стан: messages (увесь діалог), у чекпоінтері              │
│  бюджет: recursion_limit                                   │
│                                                            │
│  tools: search_kb ──┐  remember  forget  run_tests         │
└─────────────────────┼──────────────────────────────────────┘
                      │  рядок на вході, рядок на виході
   ┌─ Цикл 2: добування доказів ─ StateGraph ───────────────┐
   │  retrieve → judge → [web_fallback] → generate →        │
   │  check_support → (назад у retrieve | END)              │
   │  стан: RAGState, живе один виклик інструмента          │
   │  бюджет: attempts < 2                                  │
   └────────────────────────────────────────────────────────┘

   Цикл 3: сесії. Новий thread_id — історія порожня,
   але факти в store на місці. Команда /new у REPL.
```

**Зовнішній — агент, внутрішній — RAG.** Не навпаки: RAG це один із
інструментів, а не головний режим, інакше агент умів би тільки шукати.

Звʼязок — рівно одна функція (`devmate_lg/agent.py`):

```python
RAG_GRAPH = rag.build_rag_graph()          # компілюється один раз

@tool
def search_kb(query: str) -> str:
    out = RAG_GRAPH.invoke({"query": query, "attempts": 0, "tenant": tenant})
    ...
```

Скомпільований граф — звичайний `Runnable`, тому **підграф як інструмент це
просто виклик функції**, ніякої особливої інтеграції.

### Розмін, заради якого так зроблено

Рефлексивний цикл спалює 3–6 викликів моделі. **Жоден не потрапляє в контекст
агента** — нагору піднімається один `ToolMessage`. Це та сама гігієна
контексту, що й у памʼяті (`04:800`, «лише стабільні факти»), але застосована
до результату інструмента.

Альтернатива — підключити RAG підграфом-вузлом (`add_node("rag", rag_graph)`;
LangGraph так уміє, стан тоді спільний по однакових ключах). Тоді сміття
рефлексії осідає в `messages` і зʼїдає вікно за три питання. **Ізоляція стану
важливіша за спостережуваність.** Ціна — траєкторія не видна ззовні, тому
підграф веде власний `history`, а REPL показує його по `/trace`.

## Що прибралось саме собою: `decide_retrieval`

У Self-RAG є токен `Retrieve: yes/no` (`04:1146`) — рішення «а чи треба взагалі
шукати». У ручній версії (`../02_rag/r3_agentic_rag.py`) під нього був окремий
виклик моделі, вузол `route`.

Тут його **немає взагалі**, і це не спрощення: рішення шукати — це і є рішення
моделі покликати інструмент `search_kb`. Ручний роутер сховався у фреймворк.
Найкращий приклад «ручна реалізація зникла» в усьому блоці.

## Пʼять вузлів підграфа

| Вузол | Викликів LLM | Що це по теорії | Конспект |
| --- | --- | --- | --- |
| `retrieve` | 0 | запит до Qdrant: вектор + фільтр по `tenant` | r2/r3, r6 |
| `judge` | 1 | Self-RAG **IsRel** + CRAG **evaluator** злитно | `04:1147`, `04:3095` |
| `web_fallback` | 0 | CRAG-корекція джерела | `04:3183` |
| `generate` | 1 | відповідь строго за контекстом, з цитатами | `04:1039` |
| `check_support` | 1 | Self-RAG **IsSup** | `04:1148` |

Три виклики моделі на щасливому шляху.

`judge` злитий свідомо: Self-RAG IsRel і CRAG evaluator обидва судять якість
retrieval і відрізняються тільки формулюванням. Порізно це +1 виклик і +1
питання «а чим вони відрізняються», на яке в масштабі демо чесної відповіді
немає. Розвести назад (`04:1180`) — ~25 рядків і ще один вузол.

**Найцінніший вузол — `check_support`.** Він дивиться на **відповідь проти
контексту**, а не на контекст проти питання. Це різні перевірки, студенти їх
зливають, і першої немає в жодному з 27 прикладів `../../lecture_examples/`.

Вердикти — Pydantic, поле з обґрунтуванням мусить бути **actionable**:
`SupportVerdict.missing` іде прямо в наступну спробу пошуку, інакше друга
спроба не відрізняється від першої. Окремого вузла `rewrite` з викликом моделі
через це не потрібно: чого бракує, критик уже сказав.

## Сцена, заради якої існує `web_corpus.py`

Спитайте те, чого в нотатках немає:

```
› Як відкотити реліз на проді?
[RETRIEVE] 'Як відкотити реліз на проді?' -> d3=0.431  d4=0.384  d5=0.378
[JUDGE] relevant=[] needs_web=True — жодна нотатка не про відкат релізу
[WEB] w1: ok
[WEB] w2: ok
[WEB] w3: ok
[WEB] w4: ЗАБЛОКОВАНО — скидання попередніх інструкцій
[GENERATE] за ['w1', 'w2', 'w3']
[SUPPORT] yes
```

CRAG чесно виправив промах пошуку, пішов у зовнішнє джерело — і приніс звідти
інʼєкцію. **Корекція джерел розширює поверхню атаки**: це та ціна, про яку
конспект говорить абстрактно (`04:1178`, «необхідність уважно будувати
guardrails»). `scan()` стоїть саме на цій межі.

У `../02_rag/r5_poisoned_corpus.py` отрута лежала в основному корпусі; тут
основний корпус чистий, а отрута чекає зовні — там, куди агент піде сам.

### Годину замкнено: `/search таймзони`

На кроці 4 демо памʼяті повнотекстовий індекс не знаходив «таймзони», коли в
архіві записано «таймзонами» (`../01_memory/docs/hermes-mapping.md:124`). Запис
той самий, запит той самий, результат інший:

```
› /search таймзони
0.632 Планувальник звітів рахує дедлайни з таймзонами користувача.
0.409 Борис — викладач агентних систем (AI agents).
```

Поразка не відтворюється — і полагоджена вона **одним рядком конфігурації**:
`InMemoryStore(index={"embed": ...})`. Не новим модулем.

### `interrupt()` — друга за важливістю річ після `compile()`

```
› Запамʼятай: я віддаю перевагу коротким відповідям без емодзі.
╭─ ⏸ запис у памʼять чекає на людину ─╮
│ Борис віддає перевагу коротким…     │
│ /approve або /reject                │
╰─────────────────────────────────────╯
› /approve
```

Вона **фізично неможлива без чекпоінтера**: граф стає, стан лягає в чекпоінт,
процес може вмерти, `Command(resume=...)` продовжує. Це краще пояснення, навіщо
потрібен чекпоінтер, ніж «щоб памʼятати діалог».

І це не фігура мови — перевіряється за пів хвилини:

```
› Запамʼятай: я віддаю перевагу коротким відповідям без емодзі.
⏸ …
› /quit                                    ← процес помер із паузою всередині
$ .venv/bin/python -m devmate_lg.cli
з минулого запуску лишилась пауза:
⏸ запис у памʼять чекає на людину
› /approve                                 ← хід доїхав до кінця
```

Практичний наслідок, який варто знати: поки пауза висить, продовжити діалог
іншим питанням не можна — у чекпоінті лежить виклик інструмента без
відповіді, і модель на такій історії падає. REPL перевіряє це сам
(`waiting()` у `cli.py`) і просить спершу закрити паузу.

## Векторне сховище замість списку: `vector_store.py`

У `../02_rag/` ретрівер — це перебір списку й косинус руками. Для блоку, який
називається «умовно-продакшн», це найслабше місце: ні індексу, ні фільтра, ні
персистентності. Тут той самий корпус і ті самі вектори лежать у Qdrant
(embedded `:memory:`, без сервера й Docker — API розібраний окремо в
`../02_rag/r6_vectordb.py`).

Заміна коштувала одного рядка у вузлі `retrieve`: сигнатура та сама, на виході
ті самі `(score, doc)`. Змінилося те, чого в списку не було, — **фільтр як
частина запиту**:

```
› Чим запускати тести проєкту?
[RETRIEVE] 'Чим запускати тести проєкту?' -> d3=0.753  d4=0.487  d2=0.422
           (tenant=acme; фільтр відсік: g1)
```

`g1` — дослівна копія `d3`, але з `tenant="globex"`. Текст той самий, тому за
схожістю вона завжди поруч — і у видачу не потрапляє **тільки** через фільтр.
Це та сама ізоляція, що `facts_ns()` для памʼяті (`04:1683`, OWASP LLM08),
але іншим механізмом: памʼять ізолюється простором імен, корпус — умовою в
запиті. Нотатка `d9` у корпусі про це прямо й написана.

Тенант їде з `Context` агента у стан підграфа явно (`search_kb` →
`RAGState.tenant`), а не береться з рантайму всередині вузла: підграф — окремий
`Runnable`, і залежати від контексту виклику він не повинен. І головне — **у
виборі того, що йому дозволено бачити, модель не бере участі**.

## Що робить це умовно-продакшном

Шість речей, кожна — рядок-два, але без них це іграшка:

1. **`SqliteSaver`, не `InMemorySaver`** — переживає рестарт процесу
   (`04:622`: бекенди в окремих пакетах, підключення те саме).
2. **`interrupt()` на записі в памʼять** — людина в контурі, step-6.
3. **`namespace ("users", user_id, "facts")` + `context_schema`** — `user_id`
   не в стані (`04:792`), ізоляція тенантів адресою запису (`04:1683`,
   OWASP LLM08).
4. **Бюджети в обох циклах** — `recursion_limit` зовні, `attempts < 2`
   всередині. Замість вигадування — чесне «не підтверджено контекстом».
5. **`scan()` на обох межах** — на вході з корпусу і перед записом у store.
6. **Векторне сховище з фільтром по `tenant`** — корпус ізольований умовою
   запиту, як памʼять ізольована простором імен (`vector_store.py`).

## Три розбіжності з конспектом — назвати вголос

1. **`create_agent` проти `create_react_agent`.** Конспект (`04:1053`) пише
   `from langchain.agents import create_agent` — це інший пакет із іншим API
   (middleware замість хуків) і окремою залежністю. Ми беремо
   `langgraph.prebuilt.create_react_agent`, бо нам потрібен саме
   `pre_model_hook`. LangGraph 1.x друкує на нього попередження про переїзд —
   воно заглушене в `agent.py`, щоб не миготіло на екрані.
2. **`get_store()` проти `runtime.store`.** `04:682` радить перше, приклад на
   `04:694` використовує друге з поміткою «рекомендований спосіб». Всередині
   інструмента працює `get_store()` — його й видно в `memory_tools.py`.
   `get_runtime` при цьому живе в `langgraph.runtime`, не в `langgraph.config`.
3. **`with_structured_output()` тут не використовується.** Він примусово
   ставить `tool_choice`, а наш провайдер відповідає «Thinking mode does not
   support this tool_choice». Замість нього `PydanticOutputParser` —
   схема в промпті плюс розбір відповіді, тобто рівно те, що робить
   `with_structured_output` усередині.

## Дві межі, які варто знати заздалегідь

- **Store живе в памʼяті процесу.** Чекпоінти переживають рестарт
  (`devmate_lg.db`), факти — ні: при старті вони засіваються з `SEED_FACTS`.
  Для справжньої персистентності є `SqliteStore` з тим самим `index={...}` —
  заміна одного рядка в `agent.py`. Тут узятий `InMemoryStore`, бо нам важлива
  семантика, а не диск.
- **Свіжий факт із `remember` семантично не знайдеться.** Його вектора немає в
  кеші, а мережа на лекції не потрібна: запис зберігається і видно його в
  `/memory`, але не в `/search`. У консолі це видно рядком `[EMBED]`.
  Лікується перерахунком кеша: `python ../02_rag/build_vectors.py`.

```
  memory_tools.py remember під interrupt(), forget, читання памʼяті
  rag.py          підграф: 5 вузлів, вердикти, build_rag_graph
  vector_store.py Qdrant embedded: колекція корпусу, фільтр по tenant
  web_corpus.py   офлайнове «зовнішнє» джерело, 4 документи, один отруєний
  safety.py       копія ../01_memory/devmate/safety.py, без правок
  cli.py          REPL
  config.py       .env, шляхи, бюджети
```

`safety.py` — саме **копія, а не імпорт**: сенс сцени в тому, що цей файл
переїжджає між реалізаціями недоторканим. Копія це показує, імпорт ховає.

Корпус і вектори, навпаки, підключаються через `sys.path` (`config.py`) — тим
самим прийомом, яким `../02_rag/r5_poisoned_corpus.py` підключає `scan()`. Ні
копій, ні другого `vectors.json`.
