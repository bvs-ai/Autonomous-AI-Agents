# Крок 5 — стиснення контексту

Архів вирішив проблему обсягу, але не проблему **поточного** діалогу: довга
сесія налагодження переповнює вікно моделі сама по собі.

## Три частини історії

```
[голова]   постановка задачі — не чіпаємо ніколи
[середина] ────────► один конспект від моделі
[хвіст]    останні ходи — потрібні дослівно
```

Голова пояснює, навіщо все почалося; хвіст — що відбувається зараз.
Втратити щось із них найдорожче, тому стискається лише середина.

```python
PROTECT_FIRST = 2      # скільки перших повідомлень захищено
TAIL_RATIO = 0.3       # яку частку порогу лишаємо хвосту
THRESHOLD_TOKENS = 6000
```

## Коли стискати

```python
def should_compress() -> bool:
    history = llm.usage.prompt_history
    return bool(history) and history[-1] > THRESHOLD_TOKENS
```

Дивимось на **реальний** розмір останнього промпту, який повернув API, а не
на власну оцінку за символами. Точне число вже є — рахувати його вдруге
немає сенсу.

## Де можна різати

```python
def _user_boundaries(history: list[dict]) -> list[int]:
    return [i for i, m in enumerate(history) if m["role"] == "user"]
```

Різати можна лише по повідомленнях користувача. Якщо розрізати між викликом
інструмента і його результатом, API поскаржиться на незакритий `tool_call`.
Повідомлення користувача — завжди безпечна межа.

З тієї ж причини стиснення робиться **на межі ходу**, а не всередині:

```python
def _maybe_compress(self) -> None:
    if not compress.should_compress():
        return
    before = len(self.history)
    self.history = compress.compress(self.history)
```

## Вибір хвоста

```python
def _pick_tail(history: list[dict], boundaries: list[int]) -> int:
    budget = THRESHOLD_TOKENS * TAIL_RATIO
    for start in boundaries:
        size = sum(len(str(m.get("content", ""))) for m in history[start:]) / 3
        if size <= budget:
            return start
    return boundaries[-1]
```

Беремо найдовший хвіст, що вміщається в бюджет. Оцінка груба — 3 символи на
токен, — але це вибір межі, а не облік витрат, тож точність не критична.

## Складання результату

```python
middle = history[head_end:tail_start]
summary = _summarize(_render(middle))

return [
    *history[:head_end],
    {"role": "user", "content": f"[КОНСПЕКТ ПОПЕРЕДНЬОЇ РОЗМОВИ]\n{summary}"},
    *history[tail_start:],
]
```

Середина зникає, на її місці — одне повідомлення з конспектом.

Результат на реальному прогоні: **52 повідомлення → 17**, 25 000 символів →
7 200.

## Конспект пише модель

```python
PROMPT = """\
Стисни фрагмент робочого діалогу асистента розробника в конспект.
Це не переказ для людини, а робоча пам'ять: за конспектом асистент
має продовжити роботу так, ніби пам'ятає все сам.

Заповни розділи, порожні — пропусти:

## Задача
## Що вже зроблено
## Поточний стан
## Ухвалені рішення
## Важливі файли й команди
## Що лишилось

Пиши стисло, фактами. Зберігай точні імена файлів, команди, числа й шляхи:
саме їх асистент не зможе відновити.
"""
```

Обрізання за довжиною тут не працює: відрізнити важливе від шуму може лише
той, хто розуміє зміст. Структура розділів не дає моделі скотитися в
художній переказ, а вимога зберігати імена файлів і команди — головна, бо
саме ці деталі агент не відновить.

## Пам'ять бере участь у стисненні

```python
def _summarize(transcript: str) -> str:
    context = memory.render_all()
    block = (
        f"--- ЩО АСИСТЕНТ УЖЕ ЗНАЄ (не дублюй це в конспекті) ---\n{context}\n"
        if context else ""
    )
```

Перед конспектуванням у промпт іде поточна пам'ять. Інакше конспект
переказує вже засвоєне й марно витрачає місце.

## Стиснення нічого не втрачає назавжди

Повний текст лишається в `state.db` — його туди записав крок 4. Тому
`session_search` знайде викинуте й після стиснення.

Стискається лише те, що агент тримає **перед очима**, а не те, що він може
згадати. Це різні сховища, і в цьому вся суть їхнього поєднання.
