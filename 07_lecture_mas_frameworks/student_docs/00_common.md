# `common.py` — спільна основа трьох демо

```bash
python common.py       # смоук-тест: ключ, модель, обидва інструменти
```

Тут лежить усе, що **не** залежить від фреймворку: ключ і модель, домен,
два інструменти, друк метрик. Прочитати цей файл треба до всіх інших: далі
жоден крок не пояснює, звідки взявся `TICKET` чи `get_payments`.

## Головна думка файлу: інструмент — це звичайна Python-функція

Подивіться на `get_payments` і `refund`: ні базового класу, ні інтерфейсу,
ні анотації.

```python
def refund(payment_id: str) -> str:
    """Оформлює повернення коштів за вказаним платежем.

    Args:
        payment_id: Ідентифікатор платежу, наприклад PAY-3002.
    """
```

Опис для моделі збирається з **імені функції, сигнатури й docstring**. Тобто
docstring тут — не коментар для колеги, а частина промпту: модель читає саме
його, коли вирішує, чи викликати інструмент.

Усі три фреймворки беруть ті самі дві функції. Відрізняється лише обгортка —
і саме її ми порівнюємо далі. CrewAI єдиний із трьох вимагає декоратора
(`@tool("Get Payments")`), MAF і ADK приймають функцію голою.

## Дві деталі, які знадобляться пізніше

**«База» платежів — словник у пам'яті.** Вхід детермінований, тож уся різниця
між прогонами йде від моделі, а не від даних. Це навмисно: інакше не було б
видно, що саме плаває.

**`refund` ідемпотентний** — повторний виклик не створює друге повернення:

```python
if payment_id in _REFUNDED:
    return f"Повернення за {payment_id} вже оформлене раніше."
```

На кроці 3 це рятує демо, бо там маршрут обирає модель і вона цілком може
смикнути інструмент двічі. У проді це не хитрість демо, а базова вимога:
інструмент, який змінює стан, має бути ідемпотентним, бо викликає його
ймовірнісна система.

## `REFUND_LIMIT_USD` — бізнес-правило, а не властивість фреймворку

```python
REFUND_LIMIT_USD = 100.0
```

Ліміт, вище якого повернення вимагає людини. Знадобиться в `g3` (там за нього
відповідає функція в графі) і в `g3b` (там те саме правило написане словами
в інструкції). Порівняння цих двох файлів — головний висновок лекції про те,
які рішення віддавати моделі.

## Метрики й банер

`Metrics` рахує виклики LLM і токени, `banner` друкує однакову шапку. Завдяки
цьому вивід усіх дев'яти скриптів має однакову форму, і кроки можна класти
поруч.

Головна цифра — `викликів LLM`: саме вона показує ціну координації.

## Шум у виводі

У `common.py` вимкнено попередження, які інакше заливають екран: AFC-warning
від клієнта Gemini, `[EXPERIMENTAL]` від ADK, телеметрія CrewAI.

А от `DeprecationWarning` **навмисно не глушиться** — на кроці `g2` воно
з'явиться в коді, і це частина теми: фреймворк живий і мігрує просто зараз.

## Перевірити

```bash
python common.py
```

На екрані має бути модель, підтвердження ключа, тікет і вивід обох
інструментів. Якщо тут падає — далі йти немає сенсу, це проблема ключа
чи оточення, а не фреймворків.
