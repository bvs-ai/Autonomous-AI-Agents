# DevMate — пам'ять в агентних системах на прикладі Hermes

Навчальне демо до лекції з автономних агентних систем.

Ми беремо [Hermes Agent](https://github.com/NousResearch/hermes-agent) від Nous Research —
одну з найкращих відкритих реалізацій роботи з пам'яттю — розбираємо, як пам'ять
влаштована там, і крок за кроком будуємо власного агента на тих самих концепціях.

Демо — це **історія git**. Кожен крок має тег, і на кожному кроці агент
залишається повністю робочим:

```bash
git checkout step-1     # робочий агент без пам'яті
git checkout step-2     # + MEMORY.md / USER.md
git diff step-1 step-2  # що саме додалося
```

## Кроки

| Тег | Що додається | Розбір | Прототип у Hermes |
|---|---|---|---|
| `step-1` | Робочий агент: цикл tool-calling, інструменти, лічильник токенів | [step-1](docs/steps/step-1.md) | `run_agent.py` |
| `step-2` | `MEMORY.md`/`USER.md`, інструмент `memory`, frozen snapshot | [step-2](docs/steps/step-2.md) | `tools/memory_tool.py` |
| `step-3` | Ліміт символів, відмова замість автостиснення, самоконсолідація | [step-3](docs/steps/step-3.md) | `memory_manager.py` |
| `step-4` | `state.db` + FTS5 + `session_search` | [step-4](docs/steps/step-4.md) | `hermes_state_search.py` |
| `step-5` | Стиснення контексту + `on_pre_compress` | [step-5](docs/steps/step-5.md) | `ContextCompressor` |
| `step-6` | Фонове самонавчання після ходу + гейт `write_approval` | [step-6](docs/steps/step-6.md) | nudge counter |
| `step-7` | Захист від memory poisoning, санітизація знімка, `/forget` | [step-7](docs/steps/step-7.md) | сканер `scope="strict"` |
| `step-8` | Автопригадування з архіву, блок `<memory-context>` | [step-8](docs/steps/step-8.md) | `memory_provider.py` |

## Запуск

```bash
python -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env        # і вписати ключ
.venv/bin/python -m devmate.cli
```

Працює з будь-яким OpenAI-сумісним endpoint. Обовʼязкова умова — модель
має підтримувати tool calling.

## Команди в REPL

```
/usage     токени за сесію (промпт, відповіді, prefix cache)
/memory    стан пам'яті на диску vs заморожений знімок у промпті
/search    пошук по архіву всіх сесій
/compress  примусово стиснути контекст
/history   скільки повідомлень у контексті
/approval  on|off — вимагати підтвердження на запис у пам'ять
/pending   черга записів, що чекають підтвердження
/approve N підтвердити запис, /reject N — відхилити
/forget    видалити запис із пам'яті (без участі моделі)
/recall    on|off — автопригадування з архіву на кожному ході
/quit      вихід
```

## Чому без фреймворків

Hermes теж без них: у `pyproject.toml` лише `openai`, `httpx`, `pydantic`,
`tenacity`, `rich`, `pyyaml`. Жодного LangChain.

Причина в самому Hermes сформульована прямо: кожна залежність пінується
точною версією, а все, що не потрібне *кожній* сесії, виноситься в extras і
ставиться ліниво — «менше `dependencies` = менший радіус ураження при
наступній supply-chain атаці».

Для лекції аргумент інший, але сумісний: фреймворк ховає рівно той механізм,
який ми показуємо.

## Три види пам'яті в результаті

Агент має три сховища з різними горизонтами:

| Сховище | Живе | Обсяг | Як потрапляє в контекст |
|---|---|---|---|
| `Agent.history` | одну сесію | до вікна моделі | безпосередньо |
| `memories/*.md` | назавжди | ~1300 токенів | знімком у системному промпті |
| `state.db` | назавжди | без обмежень | на запит (`session_search`) або сама (крок 8) |

Перше стискається (крок 5), друге курується моделлю під лімітом (крок 3),
третє не обмежене нічим, бо не коштує токенів (крок 4) — і підключене
двома способами: інструментом і автопригадуванням (крок 8).

## Три шари захисту пам'яті

Пам'ять потрапляє в системний промпт, тому ін'єкція, що осіла в ній, діє в
кожній наступній сесії. Жоден шар окремо не достатній:

| Шар | Крок | Що робить | Чого не вміє |
|---|---|---|---|
| Сканер патернів | 7 | не дає записати відоме отруєння | список патернів кінцевий |
| Санітизація знімка | 7 | не пускає в промпт уже записане | не видаляє — це робить людина |
| Гейт на запис | 6 | вимагає підтвердження людини | не працює, поки вимкнений |
| Фільтр на пригадуванні | 8 | не пускає отруєне з архіву в промпт | той самий кінцевий список патернів |
